O projeto é uma aplicação dashboard de organização financeira.
O objetivo principal é registrar e organizar custos e principalmente oferecer previsibilidade das contas.

A ideia não é o registro de uma conta corrente, não haverá registro de entradas financeiras.
O registro será apenas dos gastos mensais, conseguir prever quanto será o valor final dos custos e analisar a saúde financeira de acordo com os custos reais, a depender se e quanto estiverem acima ou abaixo das médias mensais definidas para cada categoria de gasto.

Os gastos se dividirão em 3 categorias principais:
Fixos, diários e parcelas.

1.
Os gastos fixos serão aqueles que se repetirão todos os meses.
O usuário deverá poder adicionar ou excluir quantos gastos fixos quiser e definir seus valores. Deverá também poder ajustar estes valores. Estes ajustes poderão ser apenas para um mês específico ou para todos os meses subsequentes dalí pra frente.
Em algum momento do mês, o usuário informará qual foi o custo real de cada um destes gastos no mês e o aplicativo deverá indicar a situação de cada um, se está dentro do orçamento, próximo ou acima. Além desta indicação de cada custo, deverá ter a análise da situação dos gastos fixos no geral, se estão dentro do previsto, se houve uma grande margem, pouca margem, se excederam pouco ou se excederam muito o previsto.

2.
Os gastos diários serão um valor calculado de quanto o usuário pode gastar por dia.
Ele poderá inserir categorias para estes gastos e definir valores para cada uma.
A soma de todas as categorias gerará um valor total para gastos diários no mês.
Este valor total deve ser dividido por 31 para definir qual o valor que o usuário pode gastar no dia para manter as finanças dentro do previsto. O aplicativo deve calcular o valor 
O usuário poderá registrar os gastos reais que tiver em cada categoria por dia e o dashboard deve deverá e apresentar a situação dos gastos de cada dia de cada categoria, da soma dos gastos de cada categoria de cada dia e dos gastos diários totais do mês.
Caso em algum dia o usuário não tenha nenhum custo em alguma ou em todas as categorias, pode haver botões para zerar os custos do dia para cada categoria ou para zerar o dia inteiro de uma vez.

3.
O terceiro grupo de custos será o de parcelas.
O usuário poderá adicionar o valor de limite de custo com parcelas por mês e adicionar todas as compras que fizer parceladas, indicando a quantidade de parcelas.
O dashboard deve apresentar o valor total de custo com parcelas em cada mês que tiver parcelas em aberto e analisar a saúde deste grupo comparado ao valor indicado como limite.

Ou seja, o usuário poderá inserir valores previstos para todos os gastos que tiver, sejam quantos forem. Tendo a opção de excluir gastos ou alterar os valores previstos.
E com o decorrer do mês ir atualizando os custos e gastos reais, para que o aplicativo compare o que foi previsto com a realidade, faça uma análise dos custos diante do que foi previsto e o usuário tenha previsibilidade dos custos a longo prazo.

O dashboard deve utilizar abas, filtros e gráficos para apresentar análises gerais ou mais específicas, detalhadas dos custos, de forma clara e objetiva. Deve ter um visual extremamente profissional, sóbrio e clean.

O aplicativo deve ter visual responsivo para que seja visualizado em desktop ou mobile.

O aplicativo será para uso pessoal, então não há necessidade de estrutura complexa para distribuição, apenas 2 usuários terão acesso a ele. Por isso também os recursos para banco de dados e hospedagem devem ser sem custos. Mas deve ser hospedado de alguma forma que ambos possam acessar tanto em desktop ou por celular.
